# 전국 실거래 수집 대시보드

경로: `data-status.html`. 수집 설정 변경, 원본 API 호출, 재실행, Pages 설정 변경, 데이터 삭제 기능은 없다.

## 표시 기준

- 기존 `distributed-status.js`와 `collection-status.js` 로더를 재사용한다. 실제 담당 레포와 최종 이관 체크포인트, 지역 배정, 합계 자료를 검증한다.
- 전국 진행률은 완료된 시군구 × 거래유형 × 계약월 구간 / 대상 구간이다. 거래 건수의 완료율이 아니다. 반올림으로 100%를 만들지 않으며, 계획 구간 100%여도 전체 이력 검증 완료를 주장하지 않는다.
- 하나라도 담당 레포를 확인하지 못하면 `확인된 유효 거래`와 확인 레포 수를 표시한다. 미확인을 0건으로 처리하거나 부분 합계로 증가량 기준을 덮어쓰지 않는다.
- 증가량은 이 브라우저 localStorage의 직전 완전 관측과 비교한다. 첫 방문은 기준 저장만 하며 과거 증가량을 꾸며내지 않는다. 배정/대상 구간이 달라지면 비교를 새로 시작한다.
- 마지막 정상 수집 시각과 마지막 배치 기록을 구분한다. 예산 대기 작업이 최근에 상태 파일만 저장했다고 정상 수집 시각을 앞으로 당기지 않는다.
- 마지막 정상 수집 후 2시간 이상이면 저장 지연으로 표시한다. 원인을 예약 누락이라고 단정하지 않는다.
- 20개 레포의 진행률, 건수, 마지막 수집, 실패/재개 대기, 게시 산출물 용량, 조회 경로를 표로 표시한다. 예비 레포는 미배정으로 구분한다.
- 지역 검색, 시군구 상세, 거래유형/연도별 표, 마지막 배치와 로그 링크를 제공한다. 거래 본문은 내려받지 않는다.

## 갱신과 읽기 요청

- 수집 현황 JSON은 페이지가 보이고 자동 갱신이 켜진 경우 60초마다 확인한다. 이는 GitHub 수집 실행 주기를 바꾸지 않는다.
- 실행 상태는 처음 한 번 및 `실행 상태 확인` 버튼으로 공개 GitHub Actions 읽기 API를 조회한다. 15분 캐시, 이 브라우저 시간당 30회 보호, 서버 rate-limit 응답 대기를 적용한다. 토큰을 요구하거나 게시하지 않는다.
- 실행 상태의 확인 시각을 표시하며 2분 이상 지난 실행 기록을 현재 상태로 단정하지 않는다. Actions 성공과 실제 저장 결과는 별개이다.
- 사용자용 실거래 상세 화면에는 이 운영 안내를 다시 추가하지 않았다.

## 검증 범위

2026-11-12 로컬 JavaScript 회귀 테스트 106개 및 기존 Python 수집기 테스트 25개 통과. Chromium 오프라인 DOM 테스트에서 320/390/1280px 레이아웃, 20개 레포 표, 예비 레포 필터, 광명시 거래유형/연도 상세, 수집 현황 일부 조회 실패, 증가량 기준 보존과 실행 상태 조회 요청 억제를 확인했다.

브라우저 테스트는 기존 이관 스냅샷 기반 fixture와 모의 읽기 응답을 사용했으며 실제 국토부 요청이나 운영 사이트의 브라우저 검증이 아니다. 운영 배포 결과와 현재 수집 수치는 별도로 확인한다.
