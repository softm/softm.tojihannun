## 적용

- 공통 엔진 커밋: `3a29ba653e18b0844b82184d77b63a90bb992769`.
- `operations.py`에 `resumable.py`를 연결했다. 실행 요청 예산보다 큰 계약월도 검증된 임시 페이지를 보존해 이어받는다.
- 원본 페이지 총건수 및 첫 페이지 재확인을 통과하고 전체 행을 검증한 뒤에만 완료 구간을 교체한다. 임시 페이지는 Pages에 게시하지 않는다.
- 레포 001~010의 collect.yml을 검증된 엔진 SHA에 고정하고 푸시하여 실제 auto 수집을 실행했다. 매시간 실행 분은 17,19,21,23,25,27,29,31,33,35로 분산했다. GitHub cron은 정확한 실행 시각을 보장하지 않는다.
- 지역 배정, API 키, 8회/실행·8회/시간·160회/24시간의 레포별 요청 예산, 900MB 정지·1GB 게시 차단은 변경하지 않았다. 합산 요청 한도를 늘리지 않았다.
- 기존 데이터·체크포인트를 삭제하지 않았으며 Pages 설정과 서비스 조회 경로를 바꾸지 않았다. 011~020은 지역 미배정 예비 용량으로 유지한다.

## 남은 제한

- 최신 001번 상태에 아파트 전월세, 연립·다세대 전월세, 단독·다가구 전월세, 분양·입주권 매매의 HTTP 403 보류가 남아 있다. 승인/접근 원인을 별도 확인해야 하며 모든 거래유형의 전수수집이 가능하다고 확정하지 않는다.
- 현행 코드 기본 계획은 계속 진행하지만 폐지 코드와 현행 코드의 과거자료 대응 관계는 별도 검증이 필요하다. 전국 과거 전체 이력의 무누락을 이미 검증했다는 뜻이 아니다.
- 실거래 화면의 static-transactions.js는 아직 중앙 data/transactions/published/를 읽는다. 지역 레포의 신규 거래가 사용자 실거래 화면에 즉시 연동된 상태는 아니다.
- 상태 집계와 거래 조회를 구분한다. Pages 설정은 이번 실행에서 변경하지 않았다.
