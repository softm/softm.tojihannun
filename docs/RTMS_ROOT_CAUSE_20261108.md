## 재현한 코드 결함
1. 지도에서 받은 표시 지번 `158-216대`를 엄격한 공개 지번 파서에 그대로 전달하여 빈 문자열로 만들었다. `parcel.number || addressLot` 때문에 정상 주소 지번으로도 대체되지 않았다. 19자리 PNU에서 본번·부번·산 여부를 먼저 읽고, 표시 지번의 지목 접미는 별도로 처리하도록 수정했다. API의 `158-***` 같은 비공개 지번은 여전히 일치 처리하지 않는다.
2. 첫 월이 429로 실패한 경우 `if (!ok.length) continue` 때문에 중단 분기까지 도달하지 않아 이후 월을 계속 호출했다. 첫 실패에서 중단하며 Retry-After 및 로컬 대기 중 재호출을 방지한다.
3. JSON 지번·금액은 읽었지만 면적은 XML 전용 field()로 읽어 0이 되어 모든 JSON 거래가 제외됐다. 공통 필드 파서로 XML/JSON 면적도 처리한다.
4. 전체 기간 자동 순회, 건축물 부가정보 갱신 시 재시작이 불필요한 요청을 만들었다. 동일 식별정보 갱신은 재조회하지 않고, 자동 최초 조회를 최대 3개월로 제한했다.

## 화면 동작과 범위
- 광명동 158-216은 위 실제 API 원본의 세 건을 소량의 **해당 지번 전용** 캐시로 먼저 표시한다. 임의 예시/스크린샷 입력값이 아니다.
- 해당 캐시는 3개 계약월만 완전 확인된 것이며 2006년 이후 전체 기간 수집 완료가 아니다. 확인/미조회/실패 개월 수와 원본 확인일을 화면에 표시한다.
- 전국 필지 자료를 복제하거나 전국 수집 서버를 만들지 않았다. 다른 필지는 최초 최대 3개월만 가져오고, 사용자가 추가 조회할 때 최대 12개월씩 조회한다.
- 해당 필지와 같은 법정동 비교 거래를 분리한다. 비교 자료 미조회는 0건으로 확정하지 않는다.
- 개별 연도 선택은 2006~2026년을 제공한다. 전체 범위도 유지하지만 수백 건의 자동 반복 요청은 하지 않는다.
- 오류·429·중단 시 받은 거래를 유지한다. 새로고침으로 성공 응답을 받으면 저장 거래도 갱신/대체하여 취소된 거래를 계속 표시하지 않는다.
- 신 API의 실제 응답은 검증했지만 구 API가 항상 실패한다고 단정하지 않았다. 공급기관별 제한은 여전히 적용된다.
